# 보안 규칙

## 절대 금지 사항
- 커맨드 인젝션 금지 (사용자 입력을 셸 명령어에 직접 삽입 금지)
- SQL 인젝션 금지 (항상 파라미터화된 쿼리 사용)
- XSS 금지 (HTML로 렌더링되는 사용자 입력은 반드시 이스케이프)
- 소스 파일에 시크릿, API 키, 비밀번호 하드코딩 금지
- 평문 비밀번호 저장 금지

## 시크릿 관리
- 모든 시크릿은 환경변수로 관리
- `.env.example`에 필요한 변수 목록 유지 (`.env`는 절대 커밋 금지)
- 실수로 커밋된 시크릿은 즉시 교체

## 파일 & 프로세스 안전
- `rm -rf`는 명시적 확인 없이 실행 금지
- main/master에 `git push --force` 금지
- 내부 스택 트레이스를 최종 사용자에게 노출 금지

## 의존성
- 새 의존성 추가 시 사용자에게 보고 후 승인 요청
- 최근 업데이트된 잘 관리되는 패키지 우선 선택
- 새 라이브러리 추가 전 알려진 CVE 확인

## 보안 리뷰 트리거
아래 항목이 코드 변경에 등장하면 보안 리뷰 필요:
- `eval`, `exec`, `subprocess`, `os.system`
- `innerHTML`, `dangerouslySetInnerHTML`
- 문자열 연결로 구성된 Raw SQL
- 사용자 입력으로 구성된 파일 경로
