# 코딩 규칙

## 일반 원칙
- 자기 설명적 코드 작성 — 주석보다 좋은 네이밍이 우선
- 주석은 WHY가 명확하지 않을 때만 작성
- 현재 문제만 해결 — 미래 요구사항을 위한 추상화 금지
- 미사용 변수, 데드 코드, 남은 TODO 금지

## 함수 & 구조
- 작고 단일 목적의 함수
- 깊은 중첩 로직 피하기 — 조기 반환으로 처리
- 불가능한 케이스에 대한 에러 핸들링 추가 금지
- 시스템 경계(사용자 입력, 외부 API)에서만 유효성 검사

## 스타일
- 기존 파일의 들여쓰기 방식 유지
- 후행 공백 없음
- 파일 끝 개행 유지

## Git
- 커밋 메시지: 명령형, 72자 이하
- 하나의 커밋 = 하나의 논리적 변경
- 게시된 커밋 amend 금지
- 훅 스킵 금지 (--no-verify)
